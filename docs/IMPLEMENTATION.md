# AssetAtlas 实施计划

基线：PRD.md v1.0；用户指定 Next.js + Tailwind + HeroUI + Hono + Better Auth。

## 架构与约定

- 一个 Next.js Node 服务，App Router 页面；`app/api/[[...route]]/route.ts` 把全部 API 交给 Hono，包含 Better Auth。
- HeroUI v3 + Tailwind v4；360px 手机单列/底部导航，768px 紧凑侧栏，1200px 完整侧栏。
- PostgreSQL + Prisma 持久化，交互式事务与用户级 advisory lock 保存完整流水事件；十进制字符串存储、Decimal.js 计算。Better Auth 使用 Prisma Adapter。应用进程仍包含 API 与任务。
- 私有 API 从会话取用户 ID；写入校验 Origin、Zod 参数、幂等键和资源归属。
- 真实账户初始为空；`/demo` 是明确标识的只读演示，数据不进入个人账本。

## 实施顺序

1. 基础：依赖、路由、数据库、认证和邮件适配。
2. 账本：逻辑账户、标的、原子流水、余额约束、幂等、审计。
3. 估值：价格与汇率来源、手动覆盖、完整性、基线和净流入。
4. 历史：按流水重建持仓、每日 08:00 快照、版本与补跑。
5. 页面：总览、持仓/详情/录入、流水/录入、账户/安全/导出。
6. 验证：金额与流水规则、隔离、接口、构建、桌面/手机操作。

## 外部上线依赖

- 找回密码需要 Resend 发信域名与密钥，注册登录不依赖邮件；本地邮件落盘只用于开发，不代表生产邮件验收。
- CoinGecko、Frankfurter、Twelve Data、天天基金 的网络、授权和覆盖需实测；未覆盖品种用明确标识的手动价。
- HTTPS、持久化磁盘、备份保留和实际恢复演练、连续 7 天任务运行需要部署环境。
- 市场日历、供应商历史行情完整覆盖与生产负载指标须单独验收，不以界面完成代替。
